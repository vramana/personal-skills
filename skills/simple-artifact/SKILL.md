---
name: "simple-artifact"
description: "use simple artifact to explain via diagrams and less words"
---
 
- Build diagrams of before and after if a system is changed.
- Use examples to walk through complex scenarios
- Don't show files changed or no of line changed unless asked for. Focus on high level.
- User should not read the giant paragraph before seeing the diagram
- set the context in few short sentences. clear goals. 
- if you are explaining a PR. create a stack visualization on how the commits are laid out group them so it's easier to review refactors vs additions
- When creating commit stacks and visualizing them, also give each commit a simple low-risk or high-risk tag.
